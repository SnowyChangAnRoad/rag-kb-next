## 0. 结论摘要

1. **预1 打脸**：C 组重检索触发率 **35.0%**（全体）/ **38.9%**（走了检索的题），是文献 ~10% 的 **3.5–3.9 倍**。触发不是均匀分布——**in 组 0/8，out 组 3/4、partial 组 3/3**。
2. **预2 反向打脸**：相邻轮 top-3 集合相同 **20.0%**、次序相同 **0%**，远低于文献 53%。改写逐字相同仅 16.7%，改写确实在改变查询。
3. **预3 部分成立**：`cite_at_k` 正则口径 A 74.5% → C 77.8%（裁判口径 60.8% → 64.4%）。**partial 组两种口径都涨**（裁判 0.556→0.778）；但 cross 组的分母从 15 槽缩到 9 槽（2 题被判不检索：id=7/11，**生产/实验矛盾**，见 §4.1），**裁判口径下 cross 实际持平在 0.667**，正则口径的 0.733→0.889 是分母缩小的产物；in 组在正则口径下反而从 0.708 跌到 0.667。正确率 cross 组 4/5 → 3/5。
4. **预4 部分成立**：C 组 token **2.61×**、成本 **2.17×**（均低于文献上限 3.3×），延迟 **2.73×**（低于预测 ×3–5）；**B 组成本 2.05× 打脸预测 1.05–1.15**（固定两轮把 hits 翻倍送进 prompt）。
5. **预5 成立**：D2 token **0.03×**、延迟 **7.5ms**（低于预测区间 10–50ms）、D1 写过缓存的 18 题 **100% 命中**。
6. **通关③ 是负结果**：「A 错 / C 对」**0 例**；反向「C 错 / A 对」**1 例**（id=11）。C 组的全部净损失（cross 召回 0.9 → 0.5、正确率 19/20 → 18/20）**完整落在 id=7、id=11 两题**，与检索质量无关。
7. **生产 vs 实验的矛盾**：id=7、id=11 是**通用原理题**（「为什么 embedding 比关键词好」「送进 LLM 前还能做哪些处理」），实测**不检索也能答好**（C 组答案正确且完整）。gate 判「不检索」在生产上是合理行为，却在评测口径下被算作丢分——这是**题面无库锚点、却要求命中库内 gold** 造成的口径错位，**不是 gate 缺陷**（见 §4.1）。

## 3. 通关五问作答

### ① 触发率 vs 文献 10%（含"与上一轮完全相同"对照 53%）

触发率 **35.0% / 38.9%**（双分母），是文献的 3.5–3.9 倍；"与上一轮 top-3 完全相同"**20.0%（集合）/ 0%（次序）**，是文献 53% 的**反向**。

差异归因（三条，均可由本批数据支持）：
1. **自评判据是单向的**：本项目只问"本轮证据够不够"，不问"重查是否可能更够"。out 题在库里不存在可命中的 gold ⇒ 每轮必然判不足 ⇒ 必然重查，直到 cap 掐断。文献的低触发率应来自"重检索收益预期"这第二个判据。
2. **库小 + RECALL_K=10**：召回池高度重叠，本应导致重查拿到同一批块——这与预2 的方向一致，但实测重复率只有 20%，说明改写确实改变了查询；两个数字必须成对读。
3. **B 组 100% 是结构性触发**（固定两轮），不进入与文献的对照。

### ② step cap 与语义缓存各挡哪一条失败模式

SoK（arXiv 2603.07379）三条：复合幻觉传播 / 记忆投毒 / 级联工具执行漏洞。

- **step cap 挡「级联成本型失败」**，有数据：C 组 3 道触顶题里 2 道是 out、1 道是已满 gold 的 partial；无 cap 时 out 题会无限"改写-重查"且永远拿不到证据。**没有测到复合幻觉传播**——out 题不产生中间结论，本数据集构不成该链路。
- **语义缓存挡「重复计算成本」**（D2 llm_calls 0.20 vs C 3.85、token 0.03×、命中趟 7.5ms）。它**不挡幻觉传播**，反而引入"错误答案被同义问题复用"的新风险，因此约束是：只缓存 v1 正常检索出口（gate 不检索 / 0 命中不入缓存）+ namespace 精确匹配全部检索参数。

### ③ "标准 RAG 答错 / Agentic 答对"实例

**0 例。** 反向 1 例（id=11：A ✅ / C ❌）。

原因：A 组 19/20 = 95.0%，天花板效应下 C 只能在剩下 1 题赢；而 C 丢掉的两道（7、11）是**通用原理题**，gate 判了不检索——**不检索也能答好**，评测因无引用判错（§4.1）。**预注册"预期 cross 有差异"的假设被证伪**；引用口径下差异方向为负，但答案质量并未下降。

### ④ step cap=3 的依据（来自自己数据）

逐轮 gold 进展（C/D1 全 20 题）：

| 触顶题 | 题型 | 每轮 top-3 gold 命中 | 融合池 | 第 2/3 轮增量 |
|---|---|---|---|---|
| id=10 | out | [] [] [] | 0/0 | 无 gold 可增 |
| id=27 | out | [] [] [] | 0/0 | 无 gold 可增 |
| id=22 | partial | 1 → 1 → 1 | 1/1 | **0** |
| id=9（D1） | out | [] [] [] | 0/0 | 无 gold 可增 |

**cap 的边际收益为 0，3 从未被"需要"过**。共 7 个触顶实例（C 3 个 + D1 4 个，去重 4 题：9/10/22/27），其中 3 道是 out（9/10/27，无 gold）、唯一有 gold 的 id=22 首轮已满。它的真实作用是**收敛保险**（掐死 out 题的空转），不是"刚好够"。据此若收紧，cap=2 在本数据集上指标不变且省一轮检索；保留 3 只能以"给 W5 真多跳集留余量"为理由，不能写成"数据证明 3 是对的"。

### ⑤ LangGraph 状态图映射

```text
[START] → (D 组) cache_lookup ──命中──→ [replay] → END
                  │未命中
                  ↓
                [gate] ──need_retrieval=False──→ [generate_noretr] → END
                  │True
                  ↓
             [retrieve] ←────────────────────────┐
                  ↓                                │
             [self_eval] ──sufficient──→ [generate] → END
                  │不足                              ↑
                  ↓                                  │
              [rewrite] ──query 与上轮逐字相同───────┘
                  │新 query
                  └────────→（回到 retrieve，round+1）
```

映射要点：
- `max_rounds` → 状态里的轮次计数器 + `recursion_limit`（双保险，两者都是硬约束，不靠提示词）；
- 三个出口判断 → `add_conditional_edges`；出口只决定"停不停"，**不改生成路径**；
- `hits_list` / `question_list` → 状态字段 + `operator.add` reducer 累加；
- 本地 trace 落盘 ↔ LangGraph **checkpointer**（同一份状态快照，可重放 D2 命中趟）。

## 4. badcase

### 4.1 生产 vs 实验的口径错位：2 例「不检索也能答好」

判据：`terminate_reason == "gate_no_retrieve"` 且该题**有 gold**（out 题无 gold，判不检索在生产上同样合理，一并剔除）。

| 题号 | 题型 | 问题性质 | A 组（检索） | C 组（不检索） |
|---|---|---|---|---|
| id=7 | cross | 通用原理题：为什么 embedding 比关键词更可能召回语义相关内容 | ❌ 答「资料中没有相关内容」，只复述两句定义 | 裁判 ❌（无引用）；但**内容正确完整**：语义空间近邻、相似度、同义/改写/跨语言 |
| id=11 | cross | 通用方法论题：送进 LLM 前还能做哪些处理、属于哪个阶段 | ✅ 依据资料答过滤/重排/PostRetrieval，正确但视野窄 | 裁判 ❌（无引用）；但**列出 8 类后处理**（去重、重排、分块、清洗、压缩、多样性、元数据、上下文组装），覆盖更全 |

**关键事实：这两题不检索也能答得较好**（id=11 的 C 组答案甚至比 A 组更完整）。C 组判错的唯一原因是评测 gold 要求「依据库内文档」，而无检索作答没有引用槽位——**丢的是引用口径，不是答案质量**。

**这是题面与评测口径的错位，不是 gate 缺陷：**

- 题面是「通用原理/方法论」问法，没有「文档里如何讲…」这类**库锚点**；
- 评测却要求命中库内 gold —— 等价于要求模型在无提示的情况下猜到「这题必须查库」；
- 同一套 gate 判据在**生产**中恰恰是合理的：用户问通用原理时，直接作答既省钱也不丢质量。

**因此本报告不再把这两题计为「gate 误判」或「无证据作答」**，只作为评测口径局限单列（§5 第 7 条）。它对 W4 的影响是：cross 组召回 0.9 → 0.5、正确率 4/5 → 3/5，都是这个口径错位的产物，**不能作为「gate 需要修」或「Agentic 机制有害」的证据**。

补充一条事实，用于排除另一种误读：gate 的解析层并未失效，C 组 **20/20 全部命中精确标记层**（`parsed=True`），宽匹配与兜底一次都没触发。本次差异来自**判据与评测目标的定义不同**，与解析规则的松紧无关。

### 4.2 约束违反候选（严格口径）

**0 条**：所有 `self_eval_sufficient` 的题目，融合池至少含 1 条 gold。⇒ "自评说够了、证据其实不相关"这一失败模式本批未出现。

### 4.3 缓存假命中

**0 条**：18 次命中的相似度最低 0.9999994（原题重复）。

## 5. 局限（读表前必须知道）

1. **gate 的 token 不可恢复**：`gate_rec` 只落 `need_retrieval/parsed/raw`，`decide_retrieve` 的 `prompt_tokens` 未被 `run_agentic` 收下 ⇒ C/D 的 token 与成本被**系统性低估**（方向为低估，量级为每题数百 token，占 C 组 ~2200 token 的个位数百分比）。
2. **排序口径不可比**：A 组按 rerank 序，C/D 组按跨轮 RRF 融合序（不重排）。cross/in 的 recall 变化不能单独归因于"质量"。
3. **裁判噪声**：`temperature=0` 不保证逐字复现；同一批记录重跑，C 的 cite_at_k(裁判) 在 29/45 与 30/45 间漂移。**差值 < 1 槽位不得当结论**。
4. **交叉分母陷阱**：C 的 cross 组 cite_at_k 分母只剩 9 槽（id=7/11 空资料贡献 0/0），与 A 的 15 槽不可比；分母结构性缩小会制造"看起来变好"。
5. **正确率饱和**：in 10/10、out 7/7（30 题交付口径）⇒ 正确率列在本轮基本无分辨率，主读 cite_at_k + 检索层指标。
6. **重复率是 top-k 口径**：trace 每轮只落 top-3，没有全召回池 ⇒ 与文献"结果相同"不是同一个数（更严）；文献口径未公开到该粒度。
7. **评测口径 vs 生产语义**：id=7/11 是通用原理题，**不检索也能答好**（§4.1），但评测要求依据库内 gold ⇒ 被计为错。这让 cross 组的召回与正确率对比失真。后续评测集应区分「库内事实题」（必须检索）与「通用原理题」（不检索合理，不计入检索类指标），或给前者补「文档里如何讲…」的库锚点。

## 7. 结论与下一步

- **W4 的净结论**：在"单跳为主 + 2 份文档 + 证据集中"的难度下，**Agentic 循环没有可测增益**。评测口径下的净损失（cross 召回 0.9 → 0.5、正确率 4/5 → 3/5）完整落在 id=7/11 两题，而这两题**不检索也能答好**——损失来自**评测口径错位**，不是机制缺陷，也不是 gate 故障（§4.1）。
- **生产 vs 实验矛盾（本轮新增结论）**：通用原理/方法论题（如 id=7/11）不检索也能给出正确且更完整的答案，gate 判「不检索」在**生产**中是合理行为；但评测 gold 要求「依据库内文档」，无引用即判错。**同一行为在生产加分、在实验扣分**。后续评测集必须把这两类题分开：库内事实题必须检索，通用原理题不应计入检索类指标。
- **Agentic 的真实代价**：token **2.61×**、成本 **2.17×**、延迟 **2.73×**。成本主项不是 gate 本身，而是 **out 4 题全部判「检索」后空转到 cap / query_repeat**——这是真实浪费，与 id=7/11 无关。
- **缓存是净正收益**：token 0.03×、命中趟 7.5ms、无假命中 —— 这是本周唯一可直接交付的能力。
- **W5 的第一优先项**（顺序不可颠倒）：① 评测集区分「库内事实题 / 通用原理题」，前者补库锚点、后者剔除出检索类指标；② 用负证据判据压 out 题空转（**成本项，不是修 gate 误判**）；③ 在 frozen_v2 上用真多跳题验证 Agentic 是否有可测增益。
